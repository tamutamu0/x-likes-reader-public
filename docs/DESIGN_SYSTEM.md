# margin の画面設計

更新: 2026-10-12。現在の Web の基準。本人の試用に合わせて更新する。

## 目的と読む流れ

Xで気になっていいねした投稿を、自動分類された自分のライブラリへ取り込む。未読から投稿を開くと既読になり、気づいたことをメモできる。読んだ投稿もライブラリの分類・検索で見つけ直せる。保管のための追加操作は要求しない。

- 未読: 気になった投稿から読む入口。
- ライブラリ: 全件・未読・既読、自動分類と検索で過去のストックを探す入口。
- 詳細: 本文、メモ、必要な場合に記事や関連する投稿へ進む。

「あとで」「残す」「済み」の操作は置かない。メモ・タグ・分類の調整は任意。分類のための外部AI送信や著者プロフィール取得は行わない。

## 見た目と配置

Xに近い白黒と青、システムフォント、細い区切り、投稿単位の一覧を使う。取得していない著者写真を作らず、既存の著者情報または中立的な文字アバターで表示する。

| 要素 | 現在の基準 |
| --- | --- |
| 色 | 既存 app.css の text/bg/muted/line/accent を共有。青は入口・選択・リンクに使う |
| PC | 中央660pxの読書列、左232pxの入口・分類、右300pxのストック・関連 |
| 中間幅 | 左列はアイコン。1080px以下では右列を隠す |
| スマホ | 700px以下は一列。下部に未読・ライブラリ、詳細では既読切り替えとXへのリンク |
| 一覧本文 | 15px / 23px、最大7行。長文は詳細で読む |
| 詳細本文 | PC 18px / 28px、スマホ17px / 27px |
| 余白 | PC投稿20px、スマホ投稿14px。補助情報を本文より弱く見せる |
| 一覧の操作 | 既読切り替え、メモ、Xで開く。分類は小さな絞り込み入口 |
| リンク | 画像があれば横幅いっぱいの1.91比率＋見出し/説明/ドメイン。取れなければ小さな文字カード。押すと外部記事を開く。X投稿・未解決t.coはカードにしない |
| メモ | 本文の次に常時表示、自動保存。手動分類・タグと投稿情報は折りたたむ |
| 応答 | フィルター・読書状態は即時反映。押下のみ120msの控えめな変化、reduced motionを尊重 |

## 情報の整理

自動分類の件数は保存済みストックを対象とする。分類を選んだときの全件・未読・既読の件数はその分類内の件数を表示する。検索は現在の分類や読書状態に縛らず、本文・メモ・タグ・著者から探す。

分類は2段階とする。最初に大分類を選ぶと、その中の具体的なトピックがもう一列現れる。よく使う候補は6件だけ出し、選択中の候補を先頭へ置く。残りは「すべて見る」の一覧で検索・選択する。スマホは下から開く一覧にする。絞り込みの件数と既読・未読は選択トピック内の件数に合わせる。

トピックはストックの本文・見出し・メモ・タグから生まれる。例として示された製品名を固定カテゴリへ追加しない。手動の仕分けを要求せず、本人のタグへ自動で書き込まない。一覧の分類表示は大分類と具体トピックを矢印でつなぎ、クリックするとその内容を見つけ直せる。投稿には複数のトピックを認める。

関連表示には根拠を示す。「同じ記事」のまとまりに、語句が似ているだけの投稿を混ぜない。大きすぎる話題のまとまりは右列へ並べない。最初の表示は40件、以降40件ずつ保存済みデータを追加表示する。

## 実装と検証

共通の見た目は stable/public/css/reader.css、画面は js/ui/app.js と posts.js、読書状態の選択は js/core/library.js、具体トピックの抽出は js/core/topics.js。旧保存状態・本人編集の値を表示変更のために移行・破壊しない。

2026-10-13、通知に含まれる表示名と@ユーザー名を使い、Xに近いリンクカードを追加。見出し14px/20px、説明12px/17px・2行、ドメイン11px。外部HTMLを実行せず文字として表示し、画像は本人用の同一Originから読む。表示中だけ取得し、読む前の手動読み込み操作を要求しない。画像の読込失敗時も壊れた画像を残さず文字カードへ戻す。PCと390px幅を架空データで確認する。

検証は実データの閲覧と、独立した架空データでの編集確認を分ける。UI確認のために実X APIを取り直さない。iOSの画面への反映は現在保留中。
