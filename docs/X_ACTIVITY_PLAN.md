# 公式通知によるいいね更新

```text
Xの本人いいね → 署名付き通知 → 非公開core → 永続inbox → 保存 → Web / MCP
```

本人のoutbound like.createだけを購読します。通知本文があれば再取得せず、著者は通知に含まれる名前だけを使います。本文不足は既存cacheを優先し、必要なIDだけを予算内で参照します。プロフィール・引用・メディアの追加取得や、一覧の定期的な全件取得は行いません。

受信口は公開HTTPSですが、署名検証とactor一致が必須です。受信口にDB・一覧・ユーザーOAuthを置かず、内部RPCで非公開coreへ渡します。coreが署名を再検証し、保存後にACKします。UUIDを使って重複課金予約と二重反映を防ぎます。

購読は1時間の有限lease。15分Cronで残高と予算を確認し、残り30分以下で自アプリの購読を置換します。作成結果が不明なら、一覧で条件を確認するまで新規作成を繰り返しません。障害時は既存leaseの自然失効を最後の保護にします。

月・累計予算、無料残高のバッファ、個別の絶対停止日を併用します。停止日はcontrol.freeStopAtに保存し、欠落・不正なら停止します。通知予約額を実請求額と混同せず、アカウント側の上限の適用範囲も別途確認してください。配信後の拒否で既に発生した料金は取り消せません。

公開料金や提供条件は変更され得ます。環境ごとの残高・請求・購読状態はローカルの運用記録で管理し、Gitへ書きません。自動チャージ・新規購入・有料アップグレードは行いません。

低頻度の取りこぼし照合、Replay、過去ストックの広範囲な再取得は未実装です。[構成](ARCHITECTURE.md)、[運用手順](CLOUDFLARE_RUNBOOK.md)、[X公式Activity API](https://docs.x.com/x-api/activity/introduction) を参照してください。
