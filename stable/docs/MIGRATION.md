# 旧データからの移行手順（未実施・承認待ち）

**この版では移行をしていません。** 旧版のデータ形式は受け取っておらず、推測もしていません。

JSON ファイルの選択・読み込み・解析・保存は、Mac での承認が済むまで画面から使えません（`public/js/approvals.js` の `jsonFileIO: false`）。

## いま用意してあるもの（margin 自身の形式だけ）
- **`public/js/core/jsonio.js`:** 解析・検査・計画を行います。
  - 対応形式：`margin-backup` v1 / `margin-items` v1
  - 上限：20MB・5,000 件。途中で中止でき、そのときは何も保存しません
  - 秘密のキーは数えるだけで、値は運びません
- **`public/js/store/repo.js` の `applyImport`:** 取り込みを反映し、取り消し用の控えを残します。
  - 既存のあなたの編集は上書きしません
- **`public/js/store/repo.js` の `undoImport`:** 取り込みを取り消します。
  - 追加した投稿は、その後触っていないものだけ取り除きます
  - 更新した取得元の値は元に戻します
- **検証範囲:** すべて架空の fixture（`tests/fixtures`）でだけ確かめています。

## 承認後の手順（案）
1. **バックアップ:** 移行の前に、margin 側のバックアップを書き出します（承認後に有効化）。旧版のデータは別担当が保全します。margin は旧 DB・旧ファイルを読み書きしません。
2. **変換:** 旧 JSON を `margin-items` 形式へ変換するアダプタを、旧形式の実物（または公式の仕様）を確認してから作ります。
   - 旧 ID・URL → `postId`
   - 本文・著者・日時・リンク → `src`
   - 既読・タグ・メモ → `user`（対応が確かな項目だけ）
3. **検査:** 解析結果（受け入れ件数、弾いた件数と理由、秘密キーの数）を表示します。
4. **プレビュー:** 追加・更新・変化なし・手元の編集を保った件数を見せ、確認してから反映します。
5. **反映:** 1 つの取引で書きます。失敗したら何も書きません。
6. **取り消し:** 取り込み単位で戻せます。
7. **承認の有効化:** `approvals.js` の `jsonFileIO` を `true` にするのは、Mac での承認が済んだ後だけです。画面から変える手段はありません。
